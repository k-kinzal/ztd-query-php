13 * Prepares generated SQL against MySQL and reports unexpected rejections.
14 *
14 * MySQL validates syntax when a statement is prepared, so a statement that
15 * survives PDO::prepare() is syntactically accepted by the server under test.
16 * A fuzz run has no schema, so the grammar legitimately produces statements
17 * that reference missing columns, databases or engines; those server errors are
18 * tolerated. Any other rejection means the grammar emitted something MySQL
19 * cannot parse, which is a finding and surfaces as an Error for php-fuzzer to
20 * record.
15 * SQL PREPARE reaches the server directly, avoiding PDO's emulation fallback.
16 * Unsupported preparation and known schema or semantic rejections are inconclusive.
17 * In particular, ALGORITHM and LOCK accept identifiers in the grammar, then
18 * semantic actions reject unknown values with errors 1800 and 1801.
19 * Other syntax errors and unclassified rejections are findings. Duplicate aliases,
20 * unknown charsets, SRS restrictions, unresolved locks and recursive-CTE shape

22 * in sql_yacc.yy, which is absent in the pinned release build.
