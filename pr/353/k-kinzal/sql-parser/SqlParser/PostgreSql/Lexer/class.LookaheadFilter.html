The token substitutions PostgreSQL makes between its scanner and its parser.

A few keywords mean something else when a particular keyword follows: NOT before LIKE is the NOT of the predicate, WITH before TIME belongs to a type name. The parser's own lexer wrapper looks one token ahead and renames them, and it also finishes Unicode literals, which may carry their escape character in a following UESCAPE clause.
