Grammar coverage seeds

PHP-Fuzzer inputs for sql-faker that make the generator take every production its grammar can reach from the statement rule. A fuzz target that decodes its input with sql-faker can replay a corpus to check that every statement form passes, or start fuzzing from the corpus instead of from nothing.

DatabaseVersionStart ruleSeedsProductions reachedProductions emittedLargest budget
MySQLmysql-8.4.7simple_statement_or_begin21353114 / 31142610 (83.8%)50
PostgreSQLpg-17.2stmt26393387 / 33873292 (97.2%)41
SQLitesqlite-3.47.2cmd294434 / 434424 (97.7%)43

A production is reached when the derivation selects it and emitted when its tokens survive the dialect's rewrite step into the SQL text. Every corpus reaches all of its productions; the manifest next to it lists the ones the rewrite step replaces.

Layout

packages/sql-faker/seeds/
  mysql/mysql-8.4.7/<rule>-<ordinal>.txt   one PHP-Fuzzer input per file
  mysql/mysql-8.4.7.json                   manifest: target production, budget and SQL of every seed
  pg/pg-17.2/  pg/pg-17.2.json
  sqlite/sqlite-3.47.2/  sqlite/sqlite-3.47.2.json

A file is named after the rule and the alternative it was built to reach. A seed also reaches every production on its way there, so a corpus holds fewer files than productions. Manifests live next to the directories rather than inside them because PHP-Fuzzer feeds every file of a corpus directory to the target.

Contract

A seed is a byte string for SqlFaker\Generation\Choice\BytePlanCompiler, compiled under the constraints

GenerationPlan::fromRule('<start rule>')->requiringNonEmpty()

and generated by the provider of the same grammar version. That is what the syntax targets in this package's fuzz/ directory and the parse targets in packages/sql-parser/fuzz do. The first four bytes select the expansion budget relative to the constraints, so a target that adds withExpansionBudget(N) decodes the same statements as long as N is at least the corpus's largest budget from the table above. A target that prepends its own selector byte, starts at another rule, or bounds withMaxDepth() decodes different statements and needs a corpus of its own; see Building and checking.

Replaying a corpus

PHP-Fuzzer runs every file of the corpus directory before it starts mutating, so a run limited to zero mutations replays the seeds and nothing else. Run it from the package that owns the target:

cd packages/sql-parser
php -d memory_limit=-1 vendor/bin/php-fuzzer fuzz fuzz/fuzz_mysql_parse.php ../sql-faker/seeds/mysql/mysql-8.4.7/ --max-runs=0 --timeout=60
  • The first seed the target rejects is reported as CORPUS CRASH in <file> and ends the run. PHP-Fuzzer 0.0.11 still exits with status 0, so a script has to look at the output. Nothing is written to the seeds directory in this mode.
  • PHP-Fuzzer keeps the coverage features of every corpus entry in memory; the MySQL and PostgreSQL corpora exceed PHP's default memory_limit of 128M, hence -d memory_limit=-1.
  • The first input pays for the provider's one-time grammar analysis, which can take longer than PHP-Fuzzer's default limit of three seconds per input for the PostgreSQL grammar on a busy machine; pass --timeout=60 when the first seed is reported as a timeout.
  • Start PHP-Fuzzer as php vendor/bin/php-fuzzer so that environment variables such as MYSQL_VERSION or DYLD_LIBRARY_PATH reach it on macOS.
  • One seed replays with vendor/bin/php-fuzzer run-single fuzz/<target>.php ../sql-faker/seeds/mysql/mysql-8.4.7/<rule>-<ordinal>.txt.
  • The sql-faker syntax targets prepare each statement on a database; their README explains how to start it.

Fuzzing from a corpus

Copy the seeds into the target's corpus directory instead of pointing PHP-Fuzzer at seeds/: while fuzzing, PHP-Fuzzer replaces and deletes corpus files as it finds shorter inputs.

cd packages/ztd-query-mysql
mkdir -p fuzz/corpus/robustness
cp ../sql-faker/seeds/mysql/mysql-8.4.7/*.txt fuzz/corpus/robustness/
composer fuzz:robustness

The PostgreSQL robustness targets take a prefixed copy:

cd packages/ztd-query-postgres
mkdir -p fuzz/corpus/robustness
for seed in ../sql-faker/seeds/pg/pg-17.2/*.txt; do
  { printf '\0'; cat "$seed"; } > "fuzz/corpus/robustness/$(basename "$seed")"
done

Building and checking

cd packages/sql-faker
php bin/seeds.php build                    # the default release of each database
php bin/seeds.php build --tag mysql-5.7.44 # one bundled grammar version
php bin/seeds.php build --all              # every bundled grammar version
php bin/seeds.php check                    # replay and measure the committed corpora

build visits the productions in grammar order. For each one not yet reached, a guided derivation takes the shortest path to it and finishes every other symbol as cheaply as possible; SqlFaker\Generation\Choice\BytePlanEncoder records the decisions as the bytes BytePlanCompiler decodes to the same plan, and the bytes are replayed through the provider to confirm what they reach. Building the three default corpora takes a few minutes. check replays every file, fails when a seed no longer generates or a production is left unreached, and runs as the Seeds job of the package's CI workflow.

Seeds depend on the generator as well as on the grammar: a change in how sql-faker derives, rewrites or spells statements can change what a seed decodes to. Rebuild the corpora whenever check fails after such a change and commit the result. Other grammar versions are not committed; build them into a scratch directory with --output when needed.
