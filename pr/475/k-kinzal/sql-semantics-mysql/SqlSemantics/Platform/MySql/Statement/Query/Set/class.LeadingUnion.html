The operands of a 5.x union before a later UNION, when the last of them is a SELECT that keeps its own LIMIT or locking clauses.

A 5.x union is a list of query blocks, each with its own clauses. A SELECT written without parentheses before another UNION keeps its own locking clauses (select_lock_type sets the lock of the tables of that block) and, in 5.6, its own LIMIT (mysql_new_select refuses only an ORDER BY there; 5.7 LEX::new_union_query refuses the LIMIT too). The same SELECT written last would give its clauses to the whole union, so this form is not a query on its own: it is only the left operand of a further UNION (SetOperation, OrderedSetOperation or another leading union), never a body, a subquery or a statement. The operands are combined to the left like every set operation.

Rule: MYSQL-LEADING-UNION-001. The output is derived by MYSQL-SET-FACTS-001 for the operation that continues it; the form needs MySQL 5.6 or 5.7, and its own LIMIT needs 5.6. Source: https://dev.mysql.com/doc/refman/5.6/en/union.html, https://github.com/mysql/mysql-server/blob/mysql-5.6.51/sql/sql_parse.cc (mysql_new_select), https://github.com/mysql/mysql-server/blob/mysql-5.7.44/sql/sql_lex.cc (LEX::new_union_query).
