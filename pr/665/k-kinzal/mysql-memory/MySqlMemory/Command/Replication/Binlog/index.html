DecimalStorage @visibility MySqlMemoryReads exact packed decimal groups without a floating-point conversion. Group widths follow the public decimal storage specification; sign and byte order are checked against positive, negative and zero native row images. Source: https://dev.mysql.com/doc/refman/8.4/en/precision-math-decimal-characteristics.html.
Events @visibility MySqlMemoryDecodes complete events from the BINLOG operand without interpreting SQL. Source: https://dev.mysql.com/doc/refman/8.4/en/binlog.html.
Format @visibility MySqlMemoryThe event layout retained by a connection after a format description. This is runtime replication state, separate from the SQL semantic structure. Source: https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_replication_binlog_event.html.
JsonChanges @visibility MySqlMemoryApplies the binary log's ordered JSON replace/insert/remove operations. This interprets runtime JSON paths, without producing or parsing SQL. Source: https://dev.mysql.com/blog-archive/efficient-json-replication-in-mysql-8-0/.
JsonStorage @visibility MySqlMemoryReads binary JSON runtime data into the existing typed JSON value model. Offsets belong to their containing document; small inline integers retain their signedness. Bounds and depth checks reject corrupt or cyclic offsets. Source: https://dev.mysql.com/worklog/task/?id=8132 (public binary format).
Reader @visibility MySqlMemoryReads bounded fields from a binary log event supplied as runtime data. Integers are little-endian unless their field explicitly requests otherwise. Source: https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_replication_binlog_event.html.
RowImage @visibility MySqlMemoryDecodes the storage values carried by row events, independently of SQL text. Source types determine byte consumption; destination domains determine integer signedness and member names. Rows use their own null bitmap over present columns.
Rows @visibility MySqlMemoryApplies decoded row images to the destination catalog and transaction journal. The event's table map supplies the source identity; no SQL is generated or parsed. Row application bypasses SQL triggers, as native row-based replay does.
Stream @visibility MySqlMemoryConnection-local binary event layout and table identities between statements. This runtime state never belongs to a retained SQL semantic value.
TableMap @visibility MySqlMemoryA source table's identity and storage types from a runtime table-map event. Optional metadata does not change the encoded row layout. The destination's catalog supplies signedness and ENUM/SET member names during application. Source: https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_replication_binlog_event.html.
TemporalStorage @visibility MySqlMemoryDecodes packed temporal values, retaining zero dates and fractional precision. Timestamps are held in UTC, matching the storage layer's representation. Source: https://mariadb.com/docs/server/reference/clientserver-protocol/replication-protocol/rows_event_v1v2-rows_compressed_event_v1.
