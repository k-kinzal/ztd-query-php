final class TablespaceCommand
    implements Command
Restricted visibility: declared "@visibility MySqlMemory". Code outside that scope must not name this declaration.

Executes the statements on InnoDB general and undo tablespaces: CREATE, ALTER, RENAME and DROP TABLESPACE, and CREATE, ALTER and DROP UNDO TABLESPACE.

Each commits the open transaction. Explicit table locks refuse the request before name and file checks; creation and undo commands resolve ENGINE first. An ENGINE option must name an enabled storage engine (ER_UNKNOWN_STORAGE_ENGINE), and InnoDB (ER_ILLEGAL_HA_CREATE_OPTION). The names mysql, innodb_system and innodb_temporary, and the names starting with innodb_, are reserved; the server has those tablespaces, and the undo tablespaces innodb_undo_001 and innodb_undo_002. Names compare with regard to letter case. A data file name must end with .ibd (.ibu for an undo tablespace) and may not repeat the file of another tablespace; ENCRYPTION 'Y' needs a keyring the server lacks, and ALTER TABLESPACE checks the keyring before the value; AUTOEXTEND_SIZE is 0 or a multiple of 4M from 4M to 4096M. A refused option is followed by the failure of the statement and an error of the engine. ALTER and DROP TABLESPACE compare an ENGINE option with the stored engine in 8.0 through 8.3, retaining the matching option's deprecation warning. Later releases refuse that option on an existing tablespace with a syntax error. An active undo tablespace is not empty (verified on native 8.0 through 9.1 servers). The emulator does not track which tables use a tablespace, so DROP TABLESPACE never finds one in use. Source: https://dev.mysql.com/doc/refman/8.4/en/create-tablespace.html, https://dev.mysql.com/doc/refman/8.4/en/alter-tablespace.html, https://dev.mysql.com/doc/refman/8.4/en/drop-tablespace.html, https://dev.mysql.com/doc/refman/8.4/en/innodb-undo-tablespaces.html.
