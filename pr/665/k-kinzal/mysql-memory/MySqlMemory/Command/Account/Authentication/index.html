AlterRecipient @visibility MySqlMemoryChecks one ALTER USER occurrence against the current account catalog before changing it. Missing accounts still validate their authentication plugin before the existence note. Batch atomicity and final errors belong to AlterRecipients.
AlterRecipients @visibility MySqlMemoryApplies account occurrences in order while retaining every failed recipient's condition. Modern releases roll back account data on failure. A session that successfully addressed its own account in that failed batch must reset its password, independently of rollback. MySQL 5.7 retains successful changes and appends its aggregate account error. Verified through ALTER USER, SHOW WARNINGS and subsequent queries on isolated servers.
CreateFactors @visibility MySqlMemoryChecks additional authentication methods after the first method has been accepted. The first omitted plugin reports the authentication-policy warning. Existing accounts reach their existence error without loading additional plugins; new accounts validate the second factor before the third. CURRENT_USER retains only its primary authentication method, including when the account was removed earlier in the same connection. Initial authentication checks a new account's primary plugin before default roles and account attributes; an existing account retains its existence outcome. Verified on live MySQL 8.0, 8.4 and 9.1 servers.
DefinerReferences @visibility MySqlMemoryReports stored definer references before modern account existence checks.
PasswordAssignments @visibility MySqlMemoryApplies the MySQL 5.6 SET list, including passwords, in update order. A refused password does not undo other assignments or stop later updates. The first error fails the statement; subsequent errors remain diagnostics. Verified with native password, user-variable and charset assignments.
