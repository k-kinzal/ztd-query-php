final class RevokeCommand
    implements Command
Restricted visibility: declared "@visibility MySqlMemory". Code outside that scope must not name this declaration.

Executes REVOKE of privileges, of roles, of PROXY, and of ALL, GRANT OPTION.

The statement commits the open transaction. REVOKE of privileges checks its privileges and level as GRANT does, though a dynamic privilege below the global level is only a warning under IF EXISTS and a dynamic privilege the server does not register is a warning; it warns of each host name. Missing accounts and grants are diagnosed once per occurrence, in account order, including after an error; IGNORE UNKNOWN USER warns about missing accounts. A database, table or routine the account holds no grant on is ER_NONEXISTING_GRANT, ER_NONEXISTING_TABLE_GRANT or ER_NONEXISTING_PROC_GRANT, a warning under IF EXISTS; the global level never is. In 8.x and later, ALL at the global level revokes every privilege at every level, using the ALL account checks without per-host warnings; in 5.x it removes only global static privileges. REVOKE of roles refuses an account or a role that does not exist (ER_UNKNOWN_AUTHID, for a role a warning under IF EXISTS); revoking a role that is not granted does nothing. REVOKE ALL, GRANT OPTION keeps the roles. In 5.x every missing account causes ER_REVOKE_GRANTS, while successful recipients keep their changes. In 8.x and later the final recipient determines that error and a failure rolls back the whole statement. REVOKE PROXY requires authority over the proxied account (see Proxies). A failed privilege or proxy REVOKE keeps successful changes in 5.x and rolls them back in 8.x and later (verified on live 5.6.51, 5.7.44, 8.0.44, 8.4.7 and 9.1.0 servers). Source: https://dev.mysql.com/doc/refman/8.4/en/revoke.html.
