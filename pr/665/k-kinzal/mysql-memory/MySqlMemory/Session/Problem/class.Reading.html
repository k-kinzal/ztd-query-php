Raises the first problem the server finds while it reads a statement, before it checks the INTO variables and opens any table.

An unknown collation after COLLATE comes first of all, as the server looks it up while it parses the statement, and so does a key part of length 0 (ER_KEY_PART_0) after it. MySQL 5.6 and 5.7 then refuse WITH CUBE (ER_NOT_SUPPORTED_YET), WITH ROLLUP with DISTINCT or ORDER BY in the same block (ER_WRONG_USAGE), then an INTO variable no stored program declares, while they parse the query block, before the problems of a union or a write (verified on live 5.6.51 and 5.7.44 servers). A CAST or CONVERT to TIME or DATETIME with a precision above 6 is found before a wrong call of a native function or a system variable the server does not know, and a table of a multiple-table DELETE that its FROM clause lacks comes after the tables the FROM clause names twice, before any table is opened (verified on a live 8.4 server).
