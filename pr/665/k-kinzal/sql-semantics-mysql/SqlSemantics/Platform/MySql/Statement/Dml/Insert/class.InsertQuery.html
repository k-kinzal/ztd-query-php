Public API: explicitly declared with @visibility public.

INSERT or REPLACE of the rows of a query (SELECT, TABLE, VALUES or a set operation), with the optional ON DUPLICATE KEY UPDATE.

Rule: MYSQL-INSERT-QUERY-001. The facts follow MYSQL-INSERT-001 with the query as the source. A standalone VALUES source supplies its rows directly. Its enclosing WITH, ORDER BY, LIMIT and locking clauses remain represented for rendering, but do not bind names or change the written rows. This role also applies to directly constructed statements, independently of parsing. Source: https://dev.mysql.com/doc/refman/8.4/en/insert-select.html. Status: Implemented.

Answers the VALUES rows the source writes, also in parentheses, after WITH, under ORDER BY, LIMIT or a locking clause, or null when the source is another query.

The server writes every row of such a source in written order: it ignores ORDER BY and LIMIT there (verified on a live 8.4 server).

Answers the query wrappers whose clauses do not participate in a standalone VALUES write.

The row expressions keep their ordinary meaning, including their own subqueries. A set operation and SELECT keep all of their clauses. Verified against MySQL 8.0, 8.4 and 9.1, including absent local variables and common-table names.
