final class Variables
Restricted visibility: declared "@visibility SqlSemantics\Platform\MySql". Code outside that scope must not name this declaration.

Resolves the type a user variable is read with, from the type of the value it holds.

An integer reads as a BIGINT (logical width 20 in MySQL 5.6 and 5.7, and 21 from 8.0). Legacy integer result metadata expands that width by the assignment character set; arithmetic keeps the logical width. A decimal reads as DECIMAL(65,30) (reported width 83 in MySQL 5.6 and 5.7, and 67 from 8.0), a double as a double, and any other value as a blob in its collation, a temporal value in latin1: a medium blob of 16777215 bytes in MySQL 5.6 and 5.7, and from MySQL 8.0 with a byte bound of 16777215 times the character set's maximum width, a long blob when that passes 16777215 bytes. A newly assigned untyped NULL is a binary medium blob. Later untyped NULL assignments preserve an entry's previous type; typed NULL assignments change the type but retain its assignment collation. An allocated, unexecuted entry is a NULL string in the operand's allocation collation. One never allocated is a binary long blob of 16777216 bytes in MySQL 5.6 and 5.7, and a binary string of 65532 bytes from 8.0 (verified through SQL on live servers and Testcontainers). Source: https://dev.mysql.com/doc/refman/8.4/en/user-variables.html.

public function assignment(Domain $domain): Domain
source§

Gives an assignment its expression result type: integer, decimal, double or string. Integer widths follow the operand; legacy metadata retains a variable operand's reported width and otherwise expands by the connection character set. MySQL 5.6 and 5.7 retain operand decimals, floating widths and unsigned decimal widths, and give every result implicit coercibility. From 8.0 floating results use DOUBLE's expression width. Verified through PDO metadata on live servers and Testcontainers.
