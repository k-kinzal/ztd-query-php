final class DerivedOptions
Restricted visibility: declared "@visibility SqlSemantics\Platform\MySql". Code outside that scope must not name this declaration.

Defines the modifier domain of the query blocks that are not the first block of their statement: derived tables, later set operands and expression subqueries.

HIGH_PRIORITY, SQL_BUFFER_RESULT, SQL_CALC_FOUND_ROWS and legacy SQL_CACHE cannot occur in these blocks in any release (ER_CANT_USE_OPTION_HERE), including uncalled stored definitions; MySQL 5.6 and 5.7 also refuse SQL_NO_CACHE there, which later releases accept. Nested expressions and CTE declarations have their own query boundaries. Verified through SQL on MySQL 5.6.51, 5.7.44, 8.0.44 and 8.4.7.

public function block(
    list<SelectOption> $options,
    GrammarRelease $release,
): RestrictedSelectOption|SelectOptionConflict|null
source§

Answers the problem the release reports first for the modifiers of one such block, in the order the server checks them.

MySQL 5.6 refuses, in written order, the first of HIGH_PRIORITY, SQL_BUFFER_RESULT, SQL_CALC_FOUND_ROWS, SQL_CACHE and SQL_NO_CACHE. MySQL 5.7 refuses a query cache modifier written last, then ALL with DISTINCT, then HIGH_PRIORITY, SQL_BUFFER_RESULT and SQL_CALC_FOUND_ROWS in that order, then the last query cache modifier. Later releases refuse ALL with DISTINCT when the block has a restricted modifier, then HIGH_PRIORITY, SQL_BUFFER_RESULT, SQL_CALC_FOUND_ROWS and SQL_CACHE in that order.
