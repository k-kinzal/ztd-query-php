Lowers user-defined variables, system variables and their scopes.

public function scoped(
    Name $variable,
    ?Name $instance,
    ?VariableScope $scope,
    bool $assigned,
): ?VariableMisuse
source§

Answers the scope misuse of a known variable read or assigned under a scope the catalog does not give it, or null. MySQL 8.0 and later report a read under the wrong scope once the statement is read, even inside a stored program body; 5.6 and 5.7 report it when the statement runs, among the other conditions of that run, so a read is left to the run there. Every release checks an assignment before any assignment of the statement takes effect, so a standalone assignment is refused once read while a stored body keeps it. A standalone assignment of a read-only variable, or of a global-only variable under a session scope, is refused the same way (verified on 5.7.44 and 8.4.7).

public function unknown(
    Name $variable,
    ?Name $instance,
    bool $assigned,
): UnknownSystemVariable|UnstructuredVariable|null
source§

Answers the problem of a system variable name the server refuses while reading (verified on 5.6.51, 5.7.44 and 8.4.7): a plain name the release does not know (ER_UNKNOWN_SYSTEM_VARIABLE), and in 5.6 and 5.7 a structured name that is no key cache name: it names a variable that takes no component (1272) or an unknown variable. From MySQL 8.0 a structured name may be a component variable, which an installed component supplies: database state, resolved when derived.
