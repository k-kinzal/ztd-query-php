SQL Semantics analyzes SQL into immutable operations, scoped expressions, and references to table and column declarations. It uses the grammar of a selected database release. Analysis requires no connection and does not execute or simulate statements. This package is the shared runtime; install the package for your database.

**This branch is an incomplete semantic-model migration.** `Semantics::analyze()` now returns concrete semantic operations. SQLite has the implemented query, declaration, insertion, mutation, and administrative forms; MySQL and PostgreSQL lowering is still being migrated. Unimplemented forms fail explicitly. The goal remains every valid statement generated by every shipped grammar; the current subset does not meet it. See the [semantic model contract](docs/semantic-model.md).

## Requirements

- PHP 8.1+ with the zlib extension

## Installation

Install the package of your database; it installs this runtime.

MySQL:

```bash
composer require k-kinzal/sql-semantics-mysql
```

PostgreSQL:

```bash
composer require k-kinzal/sql-semantics-postgres
```

SQLite:

```bash
composer require k-kinzal/sql-semantics-sqlite
```

Each package provides its dialect: `SqlSemantics\Platform\MySql\Dialect::MySql`, `SqlSemantics\Platform\PostgreSql\Dialect::PostgreSql`, or `SqlSemantics\Platform\Sqlite\Dialect::Sqlite`.

## Usage

```php
use SqlSemantics\Facade\Semantics;
use SqlSemantics\Platform\Sqlite\Dialect;
use SqlSemantics\Statement\Query\Select;
use SqlSemantics\Statement\Schema\Definition\SqliteCreateTable;
use SqlSemantics\Statement\Expression\ColumnReference;
use SqlSemantics\Statement\Reference\ResolvedColumn;

$semantics = new Semantics(Dialect::Sqlite);
$declaration = $semantics->analyze('CREATE TABLE bar (foo INTEGER, label TEXT)');
assert($declaration instanceof SqliteCreateTable);
$query = $semantics->analyze('SELECT foo FROM bar', [$declaration]);
assert($query instanceof Select);
$column = $query->field('foo')->expression;
assert($column instanceof ColumnReference);
assert($column->resolution instanceof ResolvedColumn);

$column->resolution->table === $declaration->table;              // true
$column->resolution->column === $declaration->table->columns[0]; // true
$column->type();                                                // the original TypeDescriptor
$query->toString();                                             // SELECT foo FROM bar
```

The context accepts table declarations directly or operations that provide them.
The original objects remain the targets of resolved references. Context order is
not execution order: adding an ALTER, DROP, or write request never changes another
declaration. Every statement returned by `analyzeAll()` sees the same explicit
context; declarations earlier in the script are not automatically applied.

Without a context, `foo` has an unresolved type because its declaration is absent,
and `bar` is its candidate owner. With a complete context, an absent column or an
ambiguous reference has a distinct diagnosis. Pass `Declarations::Partial` when
the supplied context intentionally omits some database declarations.

Changes create new values and assert their scope relationships:

```php
use SqlSemantics\Statement\Identifier\Name;
use SqlSemantics\Statement\Projection\Field;

$label = new Field(new ColumnReference($query->scope, new Name('label')));
$changed = $query->withFields($query->fields()->addField($label));
$changed->toString(); // SELECT foo, label FROM bar
$query->toString();   // SELECT foo FROM bar
```

An insertion from explicit rows, one from SELECT, and one from defaults are
`InsertRows`, `InsertSelect`, and `InsertDefaults`. Changing the source form
constructs the corresponding operation, retaining the original target object.

See the [semantic model contract](docs/semantic-model.md) for uncertainty,
invariants, reconstruction, verification, and the complete-language requirement.
